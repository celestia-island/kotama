Имя взято от **Котамы** (音瀬コタマ) из клуба Veritas академии Миллениум в *Blue Archive* —
специалист клуба по связи и разведке, мастер прослушки. Для этого репозитория это читается как:
*ясно видеть программу — и записывать, что она говорит*. Это одновременно CLI и библиотека —
и представление внутри shittim-chest / hikari.

## Состояние

**P0-конвейер статического анализа работает** (первый коммит 2026-11-23, единый ствол `master`).
`kotama analyze <файл>` загружает ELF/PE-файл → находит функции → декомпилирует их в
псевдо-C на уровне базовых блоков.

Проверенный охват:

| Измерение | Состояние |
| --- | --- |
| Контейнеры | ELF32 / ELF64 / PE32 / PE64 (x86 и x64) |
| Обнаружение функций | Пять каналов улик (symtab / dynsym / PE64 `.pdata` / entry / прямые цели call), у каждой строки своя provenance |
| Границы | Сначала точные границы (длины символов, `.pdata`); выводимые уточняются линейным проходом — общие хвостовые блоки больше не обрезают настоящие функции |
| Декомпиляция | Базовые блоки + комментарии с адресными якорями; **таблицы переходов плотных switch восстанавливаются** (10/10 ветвей на матрице ELF64, достоверность 100 %) |
| Детерминизм | Тот же вход — побайтово идентичный вывод при каждом запуске (предпосылка для сравнения и повторного использования знаний) |
| Проверено на | 24 цели матрицы фикстур плюс оголённые системные бинарники вроде `/bin/true` и `/bin/ls` |

Известные ограничения (охват P1): точные границы функций PE зависят от PDB (в mingw-фикстурах
его сегодня нет — покрывают цели call + линейный проход); вывод типов, восстановление структур
и дифференциальный оракул Ghidra ещё не подключены.

Проектные решения и ход работ живут в описаниях PR (проектные документы не попадают в
дерево исходников).

## Карта возможностей

| Область | Содержание | Этап |
| --- | --- | --- |
| Статика | загрузка → обнаружение функций → декомпиляция базовых блоков ✅ / вывод типов · структуры · дифференциальный оракул | P0 ✅ / P1 |
| Динамика | инъекция (Windows / Linux) → память / стек / снапшоты → сканирование / заморозка → hook / trace | P2–P4 |
| Упаковка | `hooks.toml` + исходники hook → библиотеки инъекций под платформу + манифесты (ABI / способности / дайджесты) | P4 |
| Поверхность | сервисы (REST / WS / MCP) + веб-интерфейс hikari + удалённые узлы evernight | P5–P6 |

Два фундамента, на которых стоит всё остальное:

1. **Единая абстракция адресного пространства**: образы файлов, живые процессы и снапшоты
   памяти реализуют один и тот же `AddressSpace`; обнаружение функций и декомпиляция идут
   по одному конвейеру для всех трёх.
1. **Контентно-адресуемая идентичность функций**: `kotama://<отпечаток-модуля>/<rva>` стабилен
   сквозь ASLR, перезапуски и смену машин — аннотации и выводы могут путешествовать между узлами.

## Быстрый старт

```bash
just gate                                  # fmt + clippy + test + deny
cargo run -p kotama-cli -- --version       # версия + версия ABI полезной нагрузки
cargo run -p kotama-cli -- analyze <файл>  # таблица функций в JSON (с уликами)
cargo run -p kotama-cli -- analyze <файл> --decompile --limit 8   # плюс псевдо-C
python3 tools/build_fixtures.py --run --host-samples   # матрица фикстур + дымовой прогон
```

Матрица фикстур: `x86_64-linux-gnu / x86-linux-gnu / x86_64-windows-gnu / x86-windows-gnu`
× `-O2/-O0` × 6 целей (loops / switch / indirect / strings / float / recurs). ELF запускается
нативно; PE по умолчанию через wine (`KOTAMA_WINE`, см. AGENTS репозитория, «локальные
зависимости времени выполнения»).

исследовательские образцы, явно вам переданные. Этот репозиторий **не занимается** обходом
обнаружения, антидетектом, персистентностью, кражей учётных данных или обходом античита.
Запись в память и заморозка по умолчанию выключены и требуют явной выдачи способности —
анализ только для чтения есть позиция по умолчанию.
